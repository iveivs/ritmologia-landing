# Ритмология — правила разработки для AI-агентов

Этот лендинг воссоздан по дизайн-хэндоффу из Claude Design, сохранённому
в `docs/design-handoff/` (HTML-эталон, README со спецификацией секций,
дизайн-система, скриншоты). Читай `README.md` для общей карты проекта.
Ниже — правила, которых стоит держаться при дальнейших правках.

## Что нельзя делать без явного запроса пользователя

- **Не менять копирайт.** Все тексты (заголовки, лиды, отзывы, цены,
  контакты) — финальные, согласованы с заказчиком. Правки формулировок,
  даже «улучшающие», требуют отдельного согласования.
- **Не менять токены «на глаз».** Значения токенов в `src/app/globals.css`
  — решение по дизайну, а не рефакторинг. Они уже отличаются от
  оригинального хэндоффа (`docs/design-handoff/`) осознанно, по просьбе
  владельца — см. README, «Осознанные отклонения». Источник правды —
  `globals.css`, а не хэндофф.
- **Не добавлять иконочные шрифты, emoji или сторонние UI-кит библиотеки.**
  В бренде нет иконок: индексы — mono-цифры, «+/−» аккордеона — два
  прямоугольника. Так и должно оставаться.
- **Не добавлять sticky-хедер, плавающие чаты, параллакс или
  скролл-джекинг** — явно исключены дизайном.

## Деплой на GitHub Pages — не забывай про basePath

Проект собирается как статический экспорт (`output: "export"` в
`next.config.ts`) и раздаётся с GitHub Pages из под-пути
`/ritmologia-landing/`, а не с корня домена. Из этого следует:

- **Любой новый `<Image src="/images/...">` обязан идти через
  `withBasePath()`** из `src/lib/basePath.ts`. Next.js сам добавляет
  basePath только к `next/link` и собственным бандлам — обычные строки-
  пути к файлам из `public/` он не трогает. Забыл обернуть — картинка
  будет 404 на проде, хотя локально (`npm run dev`, там basePath пустой)
  всё будет выглядеть нормально. Это самая частая ошибка при добавлении
  новых изображений.
- Нельзя использовать фичи, которых нет в статическом экспорте: API
  routes, `getServerSideProps`-аналоги, Server Actions, `cookies()`,
  next/image с дефолтным лоадером (у нас `images.unoptimized: true`).
- После правок, трогающих пути к ассетам, стоит собрать `npm run build`
  и проверить `out/index.html` на предмет `/ritmologia-landing/...` в
  путях, либо просто открыть `out/index.html` через локальный сервер
  с под-путём (не напрямую файлом — тогда relative paths врут).

## Правила вёрстки (единая система — соблюдать всегда)

Владелец прямо просил, чтобы сайт строился по правилам, а не «на глаз».
Любая правка обязана укладываться в систему из `src/app/globals.css`:

- **Только токены.** В `*.module.css` и `*.tsx` не пишем «сырые» hex/rgba,
  px/rem для шрифтов и отступов, числа для `font-weight`, `line-height`,
  `letter-spacing`. Нужно значение, которого нет, — сначала обсуди
  добавление токена, а не вставляй число в компонент.
- **Шрифты: 2 семейства, 3 веса (400/600/800), 5 размеров + 2 плавающих.**
  Не добавляй новые кегли и начертания. Новый шрифт/вес — это правка
  `layout.tsx` (подключение) и токенов.
- **Текст — только через компоненты** `ui/Typography.tsx` (`SectionLabel`,
  `SectionHeading`, `Lead`, `Body`, `Meta`, `Index`, `Accent`,
  `DisplayHeading`). Не стилизуй заголовки/подписи/абзацы в CSS секции.
- **Раскладка — только через утилиты**: `.container` (ширина и гаттер),
  `.section` (+ `--sunken`/`--ink`/`--flush-top`) для вертикального
  ритма, `.stack` (`--lg`/`--xl`) для вертикальных промежутков, `.split`
  (`--5-7`/`--7-5`/`--6-6`, `--reverse`, `--start`/`--stretch`) для двух
  колонок. Порядок детей в `.split` — всегда «текст, медиа».
- **Отступы — только из шкалы `--space-*`**; между колонками —
  `--col-gap`, между секциями — `--section-y`. Соседние секции на одном
  фоне: у второй `section--flush-top`, иначе отступ удвоится.
- **Два брейкпоинта: `900px` и `640px`.** Не вводи новые.
- **Hero на телефоне переставлен через `order`** (см. комментарий в
  `Hero.tsx` и `Hero.module.css`): правила используют `:nth-child`, поэтому
  при изменении состава колонки с текстом обнови порядок там же.
- Новый примитив в `ui/` — только если он нужен минимум двум секциям.

## Как устроен код

- Контент отделён от разметки: весь текстовый/структурный контент — в
  `src/lib/content.ts`. Если правишь текст или список (отзывы, тарифы,
  колонки футера) — правь там, а не в JSX компонентов.
- Каждая секция лендинга — отдельный компонент в `src/components/*.tsx` +
  свой `*.module.css`. Секции собираются по порядку в `src/app/page.tsx`.
- Переиспользуемые примитивы (Typography, Button, Tag, Logo, StripeRule,
  PriceCard) — в `src/components/ui/`. Изначально это порт компонентов
  из `docs/design-handoff/_ds/design-system-*/_ds_bundle.js`, но теперь
  они живут на нашей системе токенов и с оригиналом не совпадают.
- Клиентские компоненты (`"use client"`) — только там, где реально нужен
  интерактив. Сейчас это один `Reviews.tsx` (карусель со scroll-snap).
  Остальное — серверные компоненты по умолчанию.
- **Сайт не собирает и не хранит персональные данные** — это осознанное
  решение владельца (самозанятый, хочет минимум юридических хлопот).
  Секция «Запись» — три ссылки (Telegram, ВКонтакте, телефон) из
  `contactLinks`. Не добавляй формы, счётчики или сторонние скрипты,
  которые собирают данные пользователей, без явной просьбы владельца
  (для формы понадобятся бэкенд, политика ПД, согласие и уведомление
  Роскомнадзора).
- **Картинки — только WebP и заранее сжатые** (`cwebp -q 82`, длинная
  сторона по размеру показа ×2). `next/image` здесь `unoptimized`, так
  что файл из `public/images` уходит пользователю как есть.
- **Вёрстку проверяй на 320, 375, 768, 901 и на десктопе.** Владелец
  смотрит сайт с телефона. Типичные причины горизонтального скролла:
  `grid-template-columns: 1fr` (нужно `minmax(0, 1fr)`, иначе колонка
  растягивается по самому широкому содержимому) и `white-space: nowrap`.
  Проверка в консоли: `document.documentElement.scrollWidth` должен
  равняться `clientWidth`; заодно ищи элементы, у которых
  `scrollWidth > clientWidth` (слово шире колонки).
- Next.js 16 в этом проекте новее, чем в типичных обучающих данных —
  см. блок выше и `node_modules/next/dist/docs/` перед использованием
  малоизвестных API.

## Проверка изменений

После правок стоит прогонять:

```bash
npm run build   # ловит TS-ошибки и ошибки сборки
npm run lint
```

Для визуальной проверки — превью-сервер (`npm run dev`) и сверка с
`docs/design-handoff/screenshots/*.png` (эталонные скриншоты по
прокрутке) и/или `docs/design-handoff/Landing.dc.html`, который
открывается в браузере как статичный эталон.
