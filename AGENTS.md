# Ритмология — правила разработки для AI-агентов

Этот лендинг воссоздан по дизайн-хэндоффу из Claude Design, сохранённому
в `docs/design-handoff/` (HTML-эталон, README со спецификацией секций,
дизайн-система, скриншоты). Читай `README.md` для общей карты проекта.
Ниже — правила, которых стоит держаться при дальнейших правках.

## Что нельзя делать без явного запроса пользователя

- **Не менять копирайт.** Все тексты (заголовки, лиды, отзывы, цены,
  контакты) — финальные, согласованы с заказчиком. Правки формулировок,
  даже «улучшающие», требуют отдельного согласования.
- **Не менять токены «на глаз».** Значения токенов в `src/styles/tokens.css`
  — решение по дизайну, а не рефакторинг. Они уже отличаются от
  оригинального хэндоффа (`docs/design-handoff/`) осознанно, по просьбе
  владельца — см. README, «Осознанные отклонения». Источник правды —
  `tokens.css`, а не хэндофф.
- **Не добавлять иконочные шрифты, emoji или сторонние UI-кит библиотеки.**
  В бренде нет иконок: индексы — mono-цифры, «+/−» аккордеона — два
  прямоугольника. Так и должно оставаться.
- **Не добавлять sticky-хедер, плавающие чаты, параллакс или
  скролл-джекинг** — явно исключены дизайном.

## Деплой на GitHub Pages — не забывай про basePath

Проект собирается как статический экспорт (`output: "export"` в
`next.config.ts`) и раздаётся с GitHub Pages из под-пути
`/ritmologia-landing/`, а не с корня домена. Из этого следует:

- **Любой новый `<Image src="/images/...">` обязан идти через
  `withBasePath()`** из `src/lib/basePath.ts`. Next.js сам добавляет
  basePath только к `next/link` и собственным бандлам — обычные строки-
  пути к файлам из `public/` он не трогает. Забыл обернуть — картинка
  будет 404 на проде, хотя локально (`npm run dev`, там basePath пустой)
  всё будет выглядеть нормально. Это самая частая ошибка при добавлении
  новых изображений.
- Нельзя использовать фичи, которых нет в статическом экспорте: API
  routes, `getServerSideProps`-аналоги, Server Actions, `cookies()`,
  next/image с дефолтным лоадером (у нас `images.unoptimized: true`).
- После правок, трогающих пути к ассетам, стоит собрать `npm run build`
  и проверить `out/index.html` на предмет `/ritmologia-landing/...` в
  путях, либо просто открыть `out/index.html` через локальный сервер
  с под-путём (не напрямую файлом — тогда relative paths врут).

## Правила вёрстки (единая система — соблюдать всегда)

> **Главный документ — [`docs/DESIGN-STANDARD.md`](docs/DESIGN-STANDARD.md)**:
> единый стандарт (цвет, шрифты, отступы, компоненты, ритм секций,
> доступность, темы) и таблица «что чем проверяется». Правила ниже его
> дополняют; при расхождении прав стандарт. Перед выкладкой:
> `npm run lint`, `npm run build` и `npm run audit:ui` (при запущенном сайте).

Владелец прямо просил профессиональный, компонентный подход: чтобы цвета,
размеры и вид меняются в одном месте. Любая правка обязана укладываться в
систему из `src/styles/tokens.css`. Это **проверяется автоматически**:
`npm run lint` запускает `scripts/check-design-tokens.mjs`, он же идёт перед
сборкой в CI. Если сторож ругается — исправляй код, а не отключай проверку.

**Токены — три слоя, ссылаться можно только вниз по списку:**
1. *Палитра* (`--red-500`, `--ink-900`, `--cream-100` …) — **только** внутри
   `tokens.css`. В компонентах палитру использовать запрещено.
2. *Роли* (`--color-accent`, `--text-strong`, `--text-inverse`,
   `--surface-page`, `--surface-inverse`, `--line-hairline` …) — то, чем
   пользуются компоненты. Нужен новый смысл цвета — добавь роль в слой 2.
3. *Шкалы* (`--fs-*`, `--fw-*`, `--space-*`, `--control-h-*`, `--radius-*` …).

Компонент может объявлять **локальные токены** из слоёв 2–3 (как `--btn-bg`
в кнопке или `--card-bg` в карточке) и описывать варианты данными, а не
копипастой правил.

- **Темы: светлая и тёмная.** Роли, которые различаются по темам, описаны в
  `tokens.css` как `light-dark(светлое, тёмное)` и **обязаны** иметь запасную
  светлую строку в блоке `@supports not` (сторож это проверяет). Не предполагай,
  что `--text-strong` тёмный, а `--surface-page` светлый: в тёмной теме они
  меняются местами. Нужен цвет, который не должен меняться (текст на светлой
  кнопке, тёмные блоки), используй неизменяемые роли (`--text-on-action`,
  `--text-inverse`, `--surface-inverse`). Акцент как **текст или линия** это
  `--color-accent-text`, а как **заливка** `--color-accent`. Любое изменение
  вида проверяй в **обеих** темах (в браузере: эмуляция `prefers-color-scheme`
  и кнопки «Авто / Светлая / Тёмная» в подвале) и на продакшен-сборке: сборщик
  переписывает `light-dark()`.
- **Только токены.** В `*.module.css` и `*.tsx` нет hex/rgb-цветов, литералов
  `font-size`/`font-weight`/`line-height`/`letter-spacing`, «сырых» px и
  `style={{…}}`. Нужно значение, которого нет, — сначала добавь токен.
- **Шрифты: 2 семейства, 3 веса (400/600/800), 5 размеров + 2 плавающих.**
  Не добавляй новые кегли и начертания. Новый шрифт/вес — это правка
  `layout.tsx` (подключение) и токенов.
- **Текст — только через компоненты** `ui/Typography.tsx` (`SectionLabel`,
  `SectionHeading`, `Lead`, `Body`, `Meta`, `Index`, `Accent`,
  `DisplayHeading`). Не стилизуй заголовки/подписи/абзацы в CSS секции.
- **Повторяющиеся блоки — только готовыми компонентами**, не копией стилей:
  кнопка — `Button` (варианты `primary | outline | dark | inverse |
  inverseOutline`, размеры `sm | md | lg` = 40/48/56 px, `square` для
  иконок), карточка — `Card`, кадр с фиксированной пропорцией — `Frame`, а
  картинка внутри — `Photo` (сам добавляет basePath), рамка телефона —
  `PhoneFrame`. Новый вариант кнопки или карточки — это несколько
  локальных токенов в их модуле, а не новый компонент.
- **Раскладка — только через утилиты** из `styles/layout.css`: `.container`
  (ширина и гаттер), `.section` (+ `--sunken`/`--inverse`/`--flush-top`) для
  вертикального ритма, `.stack` (`--lg`/`--xl`), `.split`
  (`--5-7`/`--7-5`/`--6-6`, `--reverse`, `--start`/`--stretch`) для двух
  колонок, `.self-start`. Порядок детей в `.split` — всегда «текст, медиа».
- **Отступы — только из шкалы `--space-*`**; между колонками —
  `--col-gap`, между секциями — `--section-y`. Соседние секции на одном
  фоне: у второй `section--flush-top`, иначе отступ удвоится. Но фоны секций
  **строго чередуются** (обычный / `--sunken` / обычный …, сейчас: Hero
  обычный, 01 Чему учим sunken, 02 Студия обычный, … 09 Адрес обычный, затем
  тёмная «Запись»), поэтому `flush-top` почти не нужен. Добавляя или убирая
  секцию, перекрась соседей, чтобы чередование не нарушилось.
- **Два брейкпоинта: `900px` и `640px`.** Не вводи новые.
- **Доступность и зоны нажатия.** Любая ссылка или кнопка не ниже
  `--space-5` (24px) на десктопе и `--hit-min` (44px) на телефоне; задавай
  `min-height`, а не размер шрифта. Страница имеет «Перейти к содержимому» и
  `<main id="main">`; секции, на которые ведут ссылки, имеют `id` (`programs`,
  `studio`, `teacher`, `cabinet`, `prices`, `faq`, `booking`). В футере не
  оставляй пункты без `href`. Проверка перед выкладкой: контраст текста
  ≥ 4,5:1 в обеих темах, нет горизонтального скролла на 390px, нет кликабельных
  элементов ниже 24/44px.
- **Hero на телефоне переставлен через `order`** (см. комментарий в
  `Hero.tsx` и `Hero.module.css`): правила используют `:nth-child`, поэтому
  при изменении состава колонки с текстом обнови порядок там же.
- Новый компонент в `ui/` — только если он нужен минимум двум секциям.

## Как устроен код

- Контент отделён от разметки: весь текстовый/структурный контент — в
  `src/lib/content.ts`. Если правишь текст или список (отзывы, тарифы,
  колонки футера) — правь там, а не в JSX компонентов.
- Каждая секция лендинга — отдельный компонент в `src/components/*.tsx` +
  свой `*.module.css`. Секции собираются по порядку в `src/app/page.tsx`.
- Переиспользуемые примитивы (Typography, Button, Card, Tag, Logo,
  StripeRule, PriceCard, FaqItem, Frame, Photo, PhoneFrame, MapEmbed) — в
  `src/components/ui/`. Изначально это порт компонентов
  из `docs/design-handoff/_ds/design-system-*/_ds_bundle.js`, но теперь
  они живут на нашей системе токенов и с оригиналом не совпадают.
- Клиентские компоненты (`"use client"`) — только там, где реально нужен
  интерактив. Сейчас это один `Reviews.tsx` (карусель со scroll-snap).
  Остальное — серверные компоненты по умолчанию.
- **Ссылки на Telegram берём из `telegramLinks`** (`plain`, `trial`, `question`):
  кнопки открывают чат с готовым сообщением. Не пиши `https://t.me/...` в
  компонентах руками.
- **Сайт не собирает и не хранит персональные данные** — это осознанное
  решение владельца (самозанятый, хочет минимум юридических хлопот).
  Секция «Запись» — три ссылки (Telegram, ВКонтакте, телефон) из
  `contactLinks`. Не добавляй формы, счётчики или сторонние скрипты,
  которые собирают данные пользователей, без явной просьбы владельца
  (для формы понадобятся бэкенд, политика ПД, согласие и уведомление
  Роскомнадзора).
- **FAQ** живёт в `faqItems` (`src/lib/content.ts`): секция `Faq.tsx` и
  разметка schema.org `FAQPage` строятся из одного массива, так что новый
  вопрос достаточно добавить туда. Ответы утверждены владельцем, условия
  (возраст, перенос, срок абонемента, оплата) не придумывай: спроси.
  Раскрывающийся пункт — нативный `<details>` (`ui/FaqItem.tsx`), без JS.
- **Картинки — только WebP и заранее сжатые** (`cwebp -q 82`, длинная
  сторона по размеру показа ×2). `next/image` здесь `unoptimized`, так
  что файл из `public/images` уходит пользователю как есть.
- **Вёрстку проверяй на 320, 375, 768, 901 и на десктопе.** Владелец
  смотрит сайт с телефона. Типичные причины горизонтального скролла:
  `grid-template-columns: 1fr` (нужно `minmax(0, 1fr)`, иначе колонка
  растягивается по самому широкому содержимому) и `white-space: nowrap`.
  Проверка в консоли: `document.documentElement.scrollWidth` должен
  равняться `clientWidth`; заодно ищи элементы, у которых
  `scrollWidth > clientWidth` (слово шире колонки).
- Next.js 16 в этом проекте новее, чем в типичных обучающих данных —
  см. блок выше и `node_modules/next/dist/docs/` перед использованием
  малоизвестных API.

- Адрес: подтверждено только «от метро Василеостровская около 12 минут
  пешком». Вход и этаж заказчик не подтвердил — не пиши их в тексты и
  подписи (в том числе в `alt` карты).

## Сторонние встраивания — только по клику

Карта Яндекса (`ui/MapEmbed.tsx`) и любые будущие встраивания (видео,
виджеты) должны загружаться **только после действия посетителя**: до этого
страница не обращается к чужим серверам. Так сайт остаётся без куки и
сторонних скриптов, и ему не нужны баннер cookie и отдельная политика.
Не заменяй это обычным `<iframe>` в разметке.

## Проверка изменений

После правок стоит прогонять:

```bash
npm run build   # ловит TS-ошибки и ошибки сборки
npm run lint
```

Для визуальной проверки — превью-сервер (`npm run dev`) и сверка с
`docs/design-handoff/screenshots/*.png` (эталонные скриншоты по
прокрутке) и/или `docs/design-handoff/Landing.dc.html`, который
открывается в браузере как статичный эталон.
