# Ритмология — лендинг школы барабанов

Одностраничный лендинг школы ударных в Санкт-Петербурге. Главная цель —
запись на бесплатный пробный урок (секция «Запись»), второстепенная —
продажа разовых занятий и абонемента, плюс онлайн-занятия для тех, кто не в
Петербурге.

Собран на Next.js по дизайн-референсу, сделанному в Claude Design
(HTML-прототип + дизайн-система). Исходный пакет хэндоффа сохранён в
[`docs/design-handoff/`](./docs/design-handoff) — там же
`Landing.dc.html` (эталон, открывается в браузере как есть),
`README.md` хэндоффа со спецификацией всех секций, дизайн-система `_ds/`
и скриншоты прокрутки для визуальной сверки.

## Стек

- **Next.js 16** (App Router, TypeScript, Turbopack), сборка как
  **статический экспорт** (`output: "export"`) — деплой на GitHub Pages,
  без Node-сервера
- **CSS Modules** — без Tailwind/UI-фреймворков, все значения берутся
  из единой системы токенов (см. «Дизайн-система» ниже)
- **next/font/google** — Golos Text (400, 600, 800; кириллица) +
  JetBrains Mono (400)
- Никакого стейт-менеджера — состояние карусели отзывов живёт в
  компоненте (`useRef`)
- Ни бэкенда, ни базы, ни хранения персональных данных: связь только
  через кнопки Telegram / ВКонтакте / телефон

## Деплой (GitHub Pages)

Сайт живёт на `https://iveivs.github.io/ritmologia-landing/`.

- `next.config.ts` собирает статический экспорт (`output: "export"`,
  `images.unoptimized: true` — на GitHub Pages нет Node-сервера, а значит
  и API оптимизации изображений).
- Сайт раздаётся из под-пути `/ritmologia-landing/`, а не из корня домена.
  Next.js сам добавляет этот префикс только к своим внутренним ссылкам
  (`next/link`) и бандлам (`_next/...`), но **не** к `src` картинок в
  `next/image`, если путь — обычная строка на файл из `public/`. Поэтому
  все `<Image src="/images/...">` в компонентах обёрнуты хелпером
  `withBasePath()` из `src/lib/basePath.ts` — там же лежит единственная
  константа `basePath`, которую импортирует и `next.config.ts`.
- **`.github/workflows/deploy.yml`** — при пуше в `main` собирает
  `npm run build` и публикует папку `out/` через официальные экшены
  `actions/upload-pages-artifact` + `actions/deploy-pages`.
- В настройках репозитория: **Settings → Pages → Source** должно быть
  выставлено на **«GitHub Actions»** (не «Deploy from a branch» — GitHub
  Pages сам не умеет собирать Next.js).
- `public/.nojekyll` обязателен: без него GitHub Pages прогоняет вывод
  через Jekyll, который по умолчанию игнорирует папки с `_` в начале
  имени (`_next`) — сайт без стилей и скриптов.

Если проект переедет на хостинг без под-пути (Vercel, свой домен и т.п.) —
`basePath`/`assetPrefix` в `next.config.ts` нужно убрать или обнулить, и
`withBasePath()` можно будет либо оставить (вернёт пустую строку), либо
убрать вовсе.

## Дизайн-система

Единый стандарт дизайна и вёрстки со списком проверок: [`docs/DESIGN-STANDARD.md`](docs/DESIGN-STANDARD.md).
Автоматический аудит интерфейса в браузере (контраст, шкала шрифтов, зоны
нажатия, скролл, заголовки, якоря, чередование фонов, обе темы, 390 и 1280 px):
`npm run dev` и в другом окне `URL=http://localhost:3000/ npm run audit:ui`
(нужны Node 22 и Chrome).

Единый источник правды — `src/styles/tokens.css`. Он устроен в **три слоя**,
и каждый слой может ссылаться только на вышестоящий:

| Слой | Что это | Кто может использовать |
|---|---|---|
| 1. Палитра | сырые значения: `--red-500`, `--ink-900`, `--cream-100` … | только `tokens.css` |
| 2. Роли | смысл цвета: `--color-accent`, `--text-strong`, `--text-inverse`, `--surface-page`, `--surface-inverse`, `--line-hairline` … | все компоненты |
| 3. Шкалы | шрифты, отступы, радиусы, высоты контролов, анимации | все компоненты |

Компоненты, кроме того, держат **свои маленькие локальные токены** (например,
`--btn-bg`, `--btn-h` в кнопке, `--card-bg` в карточке), собранные из слоёв 2–3.
Благодаря этому изменение делается в одном месте:

| Хочу… | Что править |
|---|---|
| Другой фирменный цвет | `--red-500/600/700` в слое 1 (или переназначить `--color-accent` на другой цвет палитры) |
| Другой фон страницы / тёмный блок | `--cream-100`, `--ink-900` в слое 1 или роли `--surface-*` в слое 2 |
| Другая высота кнопок и иконок-кнопок | `--control-h-sm/md/lg` (кнопки, стрелки отзывов и будущие поля берут их оттуда) |
| Новый вид кнопки | один класс в `ui/Button.module.css` с несколькими `--btn-*` |
| Другая карточка / кадр фото / рамка телефона | `ui/Card`, `ui/Frame`, `ui/PhoneFrame`: они едины для всего сайта |
| Другой шрифт или кегль | `layout.tsx` + `--fs-*`, `--fw-*` |

Проверено на практике: подмена трёх значений красной палитры перекрасила все
CSS-элементы (было 137 красных, осталось 0, красными остались только
растровые картинки: постер и логотип), а подмена `--control-h-md` одновременно
изменила кнопки «Онлайн», стрелки отзывов и пр.

**Сторож.** `scripts/check-design-tokens.mjs` (запускается в `npm run lint` и
перед сборкой в GitHub Actions) падает, если компонент обходит систему:
ссылается на палитру напрямую, содержит hex/rgb-цвета, литералы
`font-size`/`font-weight`/`line-height`/`letter-spacing`, «сырые» px, `style={{…}}`
или несуществующую переменную. Исключение оформляется явным комментарием
`token-check:allow-file <правила>` в начале файла (сейчас только `StripeRule`).

### Тёмная тема

Тема следует **системной** настройке (`prefers-color-scheme`), а посетитель
может выбрать вручную: маленькая иконка солнца/луны в полосе контактов вверху
страницы (показывает, на какую тему переключит; задаёт её явно) и полный выбор
«Авто / Светлая / Тёмная» в подвале (там же можно вернуться к «Авто»). Оба
переключателя синхронны (общее состояние в `ui/themeStore.ts`). Выбор хранится
только в `localStorage` браузера (ключ `theme`): без cookie, ничего никуда не
отправляется. Маленький скрипт в `<head>` применяет сохранённый выбор до
первой отрисовки, поэтому вспышки светлого экрана нет.

Как это устроено в токенах: каждая роль, которая различается по темам, это
**одна строка** `light-dark(светлое, тёмное)` в `tokens.css`; нужную сторону
выбирает `color-scheme` (системная или `data-theme` на `<html>`). Для
браузеров без `light-dark()` ниже есть блок `@supports not`, он даёт светлую
тему; сторож проверяет, что в нём есть все темизируемые роли.

Что пришлось решить именно для тёмной темы:

| Что | Решение |
|---|---|
| Красный акцент как текст на тёмном (3.3:1, ниже нормы) | отдельная роль `--color-accent-text`: в тёмной теме светлее (`--red-300`, 5.9:1). Заливки кнопок и тегов остаются `--color-accent` |
| Красные цифры на тёмных карточках | роль `--color-accent-on-inverse` (Card переопределяет `--color-accent-text` локально) |
| Кнопка «светлая на тёмном» | текст на ней задаёт `--text-on-action` (он не меняется по темам); раньше было завязано на `--text-strong`, а оно в тёмной теме светлое |
| Hover контурной кнопки | заливка цветом текста (`--text-strong` / `--surface-page`): тёмная на светлой, светлая на тёмной |
| Карточка «Абонемент» | роли `--surface-featured` и `--line-featured`: тёмная на светлой странице; в тёмной теме самая глубокая с красной рамкой |
| Постер в hero нарисован на кремовом фоне | роль `--surface-poster`: в светлой прозрачный, в тёмной постер лежит на своей кремовой плашке, как афиша |
| Логотип: чёрные части пропали бы на тёмном | знак стал inline-SVG (`ui/Logo`, контуры в `logoMarkPaths.ts`), цвета берутся из `--logo-red` и `--logo-ink` |
| Блоки «всегда тёмные» (Запись, подвал) | остаются тёмными в обеих темах (`--surface-inverse`, в тёмной ещё глубже) |
| Цвет адресной строки браузера | `viewport.themeColor` для светлой и тёмной |
| Смена темы «вразнобой» | на время смены отключаются CSS-переходы (`.theme-switching`, принудительный пересчёт стилей) |

Контраст проверен расчётом по WCAG на всех 287 текстовых элементах: в тёмной
теме 0 нарушений. В светлой остаются 7 **старых** (до тёмной темы): красные
цифры-индексы 14px на бежевых полосах (4.26:1 при норме 4.5). Лечится
затемнением акцента-текста до `--red-600`, но это чуть меняет вид светлой темы,
поэтому не сделано без решения владельца.

Правила шкал:

| Что | Правило |
|---|---|
| Шрифты | 2 семейства: Golos Text (весь текст) и JetBrains Mono (индексы, мета-строки, цифры) |
| Начертания | 3: `400` текст, `600` подписи и UI, `800` заголовки и цена |
| Размеры | 5 фиксированных: `12` / `14` / `16` / `20` / `44` px (`--fs-xs…xl`) + 2 плавающих: `--fs-h2` (22→44px), `--fs-display` (40→88px) |
| Межстрочный | 3: `1.1` заголовки, `1.3` подписи и кнопки, `1.55` текст |
| Отступы | шкала 4/8px `--space-1…8`; гаттер `--gutter` (24px); ритм секций `--section-y` (48px на телефоне → 112px на десктопе) |
| Высоты контролов | `--control-h-sm/md/lg` = 40 / 48 / 56 px |
| Сетка | 12 колонок, контейнер 1240px. Двухколоночные секции — только три раскладки: `.split--5-7`, `.split--7-5`, `.split--6-6` |
| Брейкпоинты | два: `900px` (колонки складываются, текст выше фото) и `640px` (телефоны) |
| Радиусы, линии | `2/4px`, hairline `1px`, `1.5px` у кнопок, `2px` у акцентных линеек |

Текст в секциях не стилизуется вручную: подпись, заголовок, лид, обычный
текст, мета-строка и индекс — это компоненты из `ui/Typography.tsx`. Так
все секции выглядят одинаково по построению, а не «на глаз».

**Фон страницы `#F4EAE2`** подобран под фон hero-фото (преобладающий цвет
`hero.webp`, расхождение по краям 0–2 уровня из 255), поэтому фото не
читается как прямоугольник. Если поменяете `--cream-100`, hero-фото
останется со старым фоном: его нужно будет перекрасить в самой картинке.

## Контент и копирайт

Копирайт (тексты, отзывы, цены, контакты) — **финальный, согласован с
заказчиком**. Не менять без согласования. Правки владельца после
хэндоффа: бейдж на абонементе «Выгодно» (был «Популярно»), пункт
преподавателя «Высшее муз. образование» (был «2 музыкальных
образования»). Секция «Вопросы и ответы» (`faqItems`) целиком написана по
ответам владельца: на каждый вопрос он выбирал или формулировал ответ сам
(возраст без ограничений, перенос по договорённости и сгорание занятия за
18 часов, абонемент без срока, оплата переводом или наличными и т. д.).
Не добавляйте в неё факты, которых владелец не подтверждал. Весь контент вынесен в
`src/lib/content.ts`, чтобы редактировать в одном месте, не трогая
разметку компонентов.

## Осознанные отклонения от прототипа

- **Единая типографика и отступы вместо разрозненных значений
  прототипа.** В прототипе значения были подобраны «на глаз»: кегли
  11/13/15/17/19/24/30px, пять разных межстрочных, три размера
  заголовков секций, отступы 20/40/56/100px. Всё сведено к системе выше.
  Видимые следствия: основной текст 16px (был 15), лид 20px (был 19), все
  заголовки секций одного размера (у «Чему учим» и «Запись» был крупнее),
  логотип в подвале того же размера, что в шапке, вертикальные отступы
  между секциями меньше на телефонах.
- **Шапка** перенесена внутрь общего контейнера (в прототипе логотип
  стоял на 24px от края окна и не совпадал с колонкой контента),
  знак 64px вместо 104px. На планшете вместо ссылок остаётся кнопка,
  на телефоне — знак в левом углу, надпись «Ритмология / школа барабанов»
  в правом, под ними линия и ряд из трёх ссылок по всей ширине.
  Компонент `SiteHeader` дизайн-системы не используется (он фиксирует
  размер знака).
- **Контакты в самом верху страницы.** Над шапкой стоит тонкая полоса с
  телефоном (`tel:`), Telegram `@iveivs` и маленькой иконкой темы (солнце /
  луна). Для местной школы контакты должны быть на виду с первого экрана. На
  телефоне слово «Telegram» убрано, зоны нажатия увеличены, а высота постера в
  hero уменьшена на высоту полосы, чтобы кнопка «Записаться на бесплатный
  урок» осталась на первом экране. Всё помещается в одну строку даже на 320px.
- **Telegram открывается с уже написанным сообщением**
  (`telegramLinks` в `src/lib/content.ts`): кнопка в блоке «Запись» пишет
  «Хочу записаться на бесплатный пробный урок», шапка и FAQ — «Хочу узнать
  про занятия». Пустое окно чата останавливает часть людей, готовая фраза
  снимает это. Ссылка вида `t.me/<имя>?text=…` поддерживается приложением
  Telegram; на устройстве без него просто откроется чат.
- **Hero на телефоне и планшете (≤900px) перестроен**: сначала постер, сразу
  под ним кнопка «Записаться на бесплатный урок» и подпись, затем город,
  слоган «Думай чувствуй играй» и лид. На десктопе порядок прежний
  (текст слева, постер справа). Высота постера ограничена
  `min(28.5rem, 56svh)`, чтобы кнопка оставалась на первом экране;
  верхний отступ секции сжат (`section--tight-top`). Перестановка сделана
  через `display: contents` + `order` в `Hero.module.css`, в DOM порядок
  остаётся семантическим (`h1` идёт раньше кнопки).
- **Hero-фото без рамки и скругления**, фон страницы подогнан под фото.
- **Надстрочник в hero** был «полоски + Санкт-Петербург · школа барабанов».
  «Школа барабанов» дублировала подпись логотипа прямо над ним, а полоски
  были чистым украшением, поэтому осталось только «Санкт-Петербург».
  Полоски (`StripeRule`) остались в подвале как фирменный штрих.
- **Кнопки переносят текст по умолчанию** (в прототипе `nowrap` обрезал
  длинные подписи на узких экранах; задокументированный баг прототипа).
- **Секция «Запись» без формы.** В прототипе там форма (имя, телефон,
  опыт, согласие). По решению владельца форму заменили тремя кнопками:
  Telegram (`t.me/iveivs`), ВКонтакте (`vk.com/motions`) и звонок
  (`tel:`). Так сайт не собирает и не хранит персональные данные — не нужны
  бэкенд, политика конфиденциальности под форму и уведомление
  Роскомнадзора именно из-за формы. Для этого в `Button` добавлен вариант
  `outlineOnInk` (контурная кнопка на тёмном фоне, в дизайн-системе
  такого не было). Ссылки живут в `contactLinks` (`src/lib/content.ts`).
  Если форма понадобится снова — она есть в git-истории (коммит до
  «Replace booking form with contact buttons»).
- **Картинки в WebP.** Оригинальные PNG/JPG (~11 МБ) сжаты до ~0,9 МБ, а
  весь `out/` — с 14 до 2 МБ. `next/image` у нас работает в режиме
  `unoptimized` (GitHub Pages), поэтому размер файла в `public/images`
  — это ровно то, что скачает пользователь. Новые фото сжимайте сами:
  `cwebp -q 82 in.png -o out.webp`.

## Карта (Яндекс)

В секции «Адрес» карта загружается **по клику**: до нажатия показывается
скриншот (`map-address.webp`), и страница не делает ни одного запроса к
Яндексу. После клика компонент `ui/MapEmbed.tsx` подставляет `iframe`
виджета `yandex.ru/map-widget/v1`. Это сделано намеренно: виджет ставит
куки `yandexuid` и др. каждому посетителю, а сайт принципиально ничего не
собирает. Рядом две обычные ссылки: «Построить маршрут» (общественный
транспорт от текущего положения посетителя) и «Открыть в Яндекс Картах».
Координаты и ссылки лежат в `studioMap` (`src/lib/content.ts`, в URL Яндекса
порядок «долгота, широта» в `ll`/`pt` и «широта, долгота» в `rtext`).
**Важно:** координаты дома взяты из данных страницы объекта в Яндекс Картах
(`coordinates` у `house`), а не из параметра `ll` скопированной ссылки: `ll` —
это лишь центр экрана в момент копирования, и по нему метка встаёт мимо дома
(так и вышло в первой версии, ошибка ~150 м).

## Адаптив

- Два брейкпоинта: `900px` и `640px`.
- Ниже 900px все двухколоночные секции складываются в одну колонку, текст
  всегда выше фото (в разметке порядок «текст, медиа»; слева медиа
  ставит `.split--reverse` только на десктопе).
- Ниже 640px сетка 2×2 в «Чему учим» — в одну колонку; шапка — знак и
  надпись по углам, под ними ряд ссылок; подвал — бренд, две колонки
  ссылок, контакты отдельной строкой.
- Фоны секций строго чередуются: Hero обычный → Чему учим sunken → Студия
  обычный → Преподаватель sunken → Онлайн обычный → Дневник sunken →
  Кабинет обычный → Отзывы sunken → Цены обычный → Вопросы sunken → Адрес
  обычный → Запись тёмная. Новая секция требует перекрасить соседей.
  `section--flush-top` нужен, только если две секции подряд всё же на одном
  фоне. В тёмной теме `--surface-sunken` заметно светлее страницы
  (`--ink-750` против `--ink-900`), карточки на нём — `--ink-725`.
- «Личный кабинет» (`Platform.tsx`): на десктопе три телефона в ряд, на
  телефоне — горизонтальная рейка со scroll-snap. Скриншоты
  `public/images/tyuttori-*.webp` сняты с локальной копии платформы
  (`iveivs/tutor-platform`) на демо-данных с вымышленными учениками; логотип
  `tyuttori-logo.webp` — иконка приложения из того же репозитория. Ссылка и
  подпись — `platformLink` в `content.ts`.
- Карточки цен переносятся автоматически (`repeat(auto-fit, minmax(260px, 1fr))`).
- `prefers-reduced-motion` обнуляет все transition-длительности
  (см. `styles/tokens.css`).
