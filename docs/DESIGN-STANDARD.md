# Стандарт UX/UI — «Ритмология»

Единый документ: как выглядит и ведёт себя интерфейс и как мы это проверяем.
Правила написания кода — в [`ENGINEERING.md`](ENGINEERING.md), работа с GitHub
— в [`../CONTRIBUTING.md`](../CONTRIBUTING.md). Если правило здесь расходится
с другим файлом, прав этот документ. Значения токенов живут только в
`src/styles/tokens.css`; здесь они названы по имени, чтобы документ не
устаревал при смене цвета или размера.

## 0. Как это проверяется

| Что                                                                                                                                                | Чем                                                         | Когда                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------- |
| «Сырые» цвета, px, шрифты, `style={{}}`, чужие токены, паритет тем                                                                                 | `npm run lint` (ESLint + `scripts/check-design-tokens.mjs`) | на каждый коммит и в CI         |
| Форматирование                                                                                                                                     | `npm run format:check` (Prettier)                           | в CI                            |
| Типы и сборка                                                                                                                                      | `npx tsc --noEmit`, `npm run build`                         | в CI                            |
| Контраст AA, шкала шрифтов, зоны нажатия, скролл, заголовки, `alt`, якоря, `rel=noopener`, чередование фонов; светлая и тёмная тема, 1280 и 390 px | `npm run audit:ui` (Node 22, Chrome)                        | в CI на собранном сайте         |
| Самопроверка аудита                                                                                                                                | `SELFTEST=1 npm run audit:ui` — обязан упасть               | после правок самого аудита      |
| Навигация клавиатурой, скринридер, иерархия и ритм «на глаз»                                                                                       | вручную                                                     | при новой секции или компоненте |

**Определение «готово»:** линт, форматирование, типы, сборка и `audit:ui`
зелёные; обе темы просмотрены глазами на 390 и 1280 px; README и стандарт
обновлены, если появилась секция, компонент или правило.

## 1. Токены: три слоя

1. **Палитра** (`--cream-*`, `--ink-*`, `--red-*` …): только внутри `tokens.css`.
2. **Роли** (`--surface-*`, `--text-*`, `--color-accent*`, `--line-*`): то, чем
   пользуются компоненты. Нужен новый смысл цвета — добавь роль.
3. **Шкалы** (`--fs-*`, `--fw-*`, `--lh-*`, `--space-*`, `--radius-*`,
   `--control-h-*`, `--hit-min`, `--dur-*`).

Компонент может объявлять локальные токены из слоёв 2–3 (`--btn-bg`,
`--card-bg`), но не слоя 1. Хардкод цвета, размера или шрифта в компоненте
считается ошибкой, её ловит линт. Нужного значения нет в шкале — сначала
обсуждается и добавляется токен, а не «пара пикселей в компоненте».

## 2. Цвет

Каждая тематическая роль — одна строка `light-dark(светлая, тёмная)` плюс
светлое значение в блоке `@supports not`.

| Задача                                                          | Роль                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------ |
| Фон страницы / чередующаяся полоса / карточка                   | `--surface-page` / `--surface-sunken` / `--surface-raised`   |
| Тёмный блок в обеих темах (запись, подвал, выделенная карточка) | `--surface-inverse`, `--surface-featured`                    |
| Основной / обычный / приглушённый текст                         | `--text-strong` / `--text-body` / `--text-muted`             |
| Текст на тёмном блоке                                           | `--text-inverse`, `--text-inverse-muted`                     |
| Заливка акцента (кнопка, тег, полоса)                           | `--color-accent` (+ `-hover`, `-press`, `--color-on-accent`) |
| Акцент как **текст или линия**                                  | `--color-accent-text`                                        |
| Акцент как мелкий текст (14px, цифры)                           | `--color-accent-text-small`                                  |
| Линии                                                           | `--line-hairline`, `--line-strong`, `--line-inverse`         |
| Состояния                                                       | `--status-ok`, `--status-warn`                               |

Правила:

- Не предполагай, что `--text-strong` тёмный: в тёмной теме роли меняются.
- Контраст текста к фону не ниже **4,5:1**; для крупного (≥24px или ≥18,66px
  жирного) не ниже **3:1**. Проверяет `audit:ui`.
- Акцент — это один цвет с ролями (заливка, текст, мелкий текст); использовать
  его экономно: не больше одного акцентного элемента на «смысловой кусок».
- Цвет никогда не единственный носитель смысла (цена, статус, ошибка имеют
  и текст).
- Тёмная тема — не инверсия, а отдельная настройка ролей: полосы светлее
  страницы, карточки светлее полосы, акцентный текст светлее.

## 3. Типографика

### 3.1 Состав

**2 семейства, 3 начертания, 7 размеров.** Больше нельзя.

| Роль             | Шрифт / вес                                   | Токены                       |
| ---------------- | --------------------------------------------- | ---------------------------- |
| Заголовок экрана | Golos 800, капс, плотный                      | `--fs-display`, `--lh-tight` |
| Заголовок секции | Golos 800, капс                               | `--fs-h2`, `--lh-tight`      |
| Заголовок пункта | Golos 800 (или 600)                           | `--fs-lg`, `--lh-snug`       |
| Лид              | Golos 400                                     | `--fs-lg`, `--lh-body`       |
| Основной текст   | Golos 400                                     | `--fs-md`, `--lh-body`       |
| Кнопка, UI       | Golos 600                                     | `--fs-md`, `--ls-btn`        |
| Метка секции     | Golos 600, капс, разрядка                     | `--fs-sm`, `--ls-caps`       |
| Тег              | Golos 600, капс                               | `--fs-xs`, `--ls-caps`       |
| Метаданные       | JetBrains Mono 400 (контакты, подписи, цифры) | `--fs-sm`, `--ls-mono`       |
| Цена             | Golos 800, цифры `tabular-nums`               | `--fs-xl`, `--lh-tight`      |

### 3.2 Сочетания

- В одном блоке не больше **трёх** размеров: заголовок + лид + основной текст.
  Между соседними уровнями шаг не меньше 1,25× (16 → 20 → 44), иначе иерархия
  не читается.
- Моно — только для **коротких метаданных** (одна-две строки): телефон,
  подпись, нумерация. Предложения и абзацы моно не набираются.
- Капс — только для заголовков, меток и тегов, всегда с разрядкой `--ls-caps`
  у мелких. Абзацы капсом не набираются.
- Начертаний ровно три и у каждого своя роль: 400 — текст, 600 — UI и метки,
  800 — заголовки. Курсива и подчёркивания нет; ссылка отличается цветом и
  позицией в контексте.
- Длина строки: лид до `--measure-lead` (46ch), текст до `--measure-body`
  (56ch), узкие подписи `--measure-narrow`; цель — 45–75 знаков.
- Весь текст идёт через `ui/Typography.tsx` (`SectionLabel`, `SectionHeading`,
  `Lead`, `Body`, `Meta`, `Index`, `Accent`, `DisplayHeading`). Стилизовать
  заголовки и абзацы в CSS секции нельзя. Один `h1` на страницу, уровни
  заголовков без пропусков (h1 → h2 → h3).
- Перенос слов: `text-wrap: balance` у заголовков и кнопок, `pretty` у
  абзацев; неразрывный пробел в «1 800 ₽» и подобных.

## 4. Отступы: шкала и применение

Единая шкала `--space-1…8` = 4, 8, 12, 16, 24, 32, 48, 64 px. Других значений
нет. **Закон близости:** чем теснее связаны элементы, тем меньше расстояние;
внутренний зазор всегда меньше внешнего.

| Токен       | px  | Применение                                                 |
| ----------- | --- | ---------------------------------------------------------- |
| `--space-1` | 4   | микро: значок↔текст, звёзды, вертикальные отступы в метке |
| `--space-2` | 8   | тесные пары, внутри меток и тегов                          |
| `--space-3` | 12  | между пунктами списка, между подписью и полем              |
| `--space-4` | 16  | группа кнопок, внутренний отступ плотной карточки          |
| `--space-5` | 24  | **стандарт между блоками** (`.stack`), минимальная зона    |
| `--space-6` | 32  | между группами блоков, внутренний отступ карточки          |
| `--space-7` | 48  | между крупными блоками, широкая карточка (`padXl`)         |
| `--space-8` | 64  | зарезервирован: самые крупные разрывы                      |

Между колонками — `--col-gap`, между секциями — `--section-y`, ширина и
боковое поле — `--container` и `--gutter`.

### 4.1 Margin и padding: кто за что отвечает

- **Padding** — внутреннее поле компонента (карточка, кнопка, секция).
  **Margin** компонент наружу **не задаёт**.
- **Расстояние между соседями задаёт родитель**: `gap` у flex/grid или
  утилита `.stack`. Не «margin-bottom у каждого».
- `margin-top: auto` допускается, чтобы прижать блок к низу flex-карточки
  (кнопка цены, подпись отзыва).
- `margin-inline: auto` — только у `.container`.
- Отрицательный margin — только как оптическая компенсация или для увеличения
  зоны нажатия, и всегда с комментарием «зачем».
- Боковое поле страницы даёт только `.container`; секция не добавляет своих.

### 4.2 Зоны нажатия

Любая ссылка, кнопка и `summary` не ниже **24px** на десктопе (`--space-5`) и
**44px** на телефоне (`--hit-min`). Увеличивай `min-height`/зону, а не шрифт.

## 5. Выравнивание

- **Текст выравнивается по левому краю.** Заголовки, лиды и абзацы — по левому;
  по центру только подпись кнопки и короткие значки. По ширине (justify) и
  по правому краю — нет.
- Колонка текста и колонка медиа в `.split` выравниваются по центру
  (`align-items: center`); если текст заметно выше медиа — `.split--start`.
- Строка из элементов разной высоты — по центру (`align-items: center`);
  цена и единица («1 800 ₽ / 60 минут») — по базовой линии.
- Маркер или цифра списка выравнивается по **базовой линии первой строки**
  текста (`align-items: baseline`), а не по верху: у моно-цифры и текста
  разный кегль, и по верху они расходятся.
- Числа, которые сравнивают (цены, время), — `tabular-nums`.
- Всё стоит на одной сетке: контент внутри `.container`, колонки — 12-колонная
  логика через `.split--5-7`, `--7-5`, `--6-6`. Элемент не «чуть сдвинут»:
  либо на сетке, либо это оптическая компенсация с комментарием.

## 6. Скругления, линии, тени

| Токен                                 | Значение | Где                                               |
| ------------------------------------- | -------- | ------------------------------------------------- |
| `--radius-1`                          | 2px      | элементы управления: кнопки, иконочные кнопки     |
| `--radius-2`                          | 4px      | поверхности: карточки, кадры, окно, фокус         |
| `--radius-pill`                       | 999px    | теги, точки                                       |
| `--device-radius` / `--device-border` | 20 / 6px | только рамка телефона; внутренний радиус = 20 − 6 |

Правила: один тип элемента — один радиус; вложенный радиус = внешний минус
отступ; новых радиусов не вводим. Рамки — `--border-hairline` (разделители),
`--border-strong` (подчёркивание активного), `--border-heavy` (акцентная
линия сверху пункта). Тень одна — `--shadow-raised`, только для «приподнятых»
объектов (телефон), не как украшение.

## 7. Списки

Список — это только то, что семантически является списком: **три и больше
однородных элемента**. Разметка выбирается по смыслу, а не по виду.

| Вид                          | Разметка             | Когда                                                              | Примеры у нас                               |
| ---------------------------- | -------------------- | ------------------------------------------------------------------ | ------------------------------------------- |
| Маркированный                | `<ul>`               | набор равных пунктов без порядка                                   | навигация, экраны кабинета, отзывы, вопросы |
| Нумерованный (`Index`)       | `<ol>`               | порядок важен **или** это «каталог» брендовой нумерации (01, 02 …) | «Чему учим», пункты тарифа                  |
| Раскрывающийся               | `<details>` в `<ul>` | вопросы и ответы, где ответ необязателен к чтению                  | FAQ                                         |
| Описание (термин + значение) | `<dl>`               | пары «название — значение»                                         | не используется                             |

Правила содержания и вида:

- **Нумерация (`Index`)** — моно, `--fs-sm`, дополненная нулём («01»),
  `--color-accent-text-small`. Если есть `Index`, разметка — `<ol>`.
  Нумеруем не больше 9 пунктов.
- **Маркеров-точек нет** и эмодзи нет: пункты разделяет отступ или линия;
  цифры — единственный «маркер».
- Пункты списка: не больше 7 в группе, не длиннее двух строк, параллельные по
  грамматике, с заглавной буквы, **без точки в конце** (если это не полное
  предложение).
- Расстояние между пунктами — `--space-3`; список в списке не вкладывается.
- Группа однородных карточек (экраны, отзывы) — тоже `<ul>`; `<li>` обёртка, а
  карточка внутри.
- Горизонтальная лента (отзывы, экраны кабинета на телефоне) — `<ul>` со
  scroll-snap; управление доступно кнопками и свайпом, а не только жестом.

## 8. Компоненты (`src/components/ui/`)

`Button` (варианты `primary | outline | dark | inverse | inverseOutline`;
размеры `sm | md | lg` = 40 / 48 / 56 px; `square`), `Card` (тона
`paper | plain | sunken | featured | inverseOutline`), `Frame` + `Photo`, `PhoneFrame`
(`cutout | dark`), `Tag`, `Logo`, `StripeRule`, `PriceCard`, `FaqItem`,
`MapEmbed` (встраивание только по клику), `ThemeToggle`, `ThemeIconButton`,
`Typography`.

- Блок, который повторяется в двух местах, — компонент. Новый вид кнопки или
  карточки — несколько локальных токенов в их модуле, а не новый компонент.
- **Состояния** любого интерактивного элемента: обычное, наведение
  (`--transition-ui`: цвет, фон, рамка), нажатие (смещение `--press-offset`),
  фокус (`:focus-visible`, кольцо `--focus-ring`, ширина `--focus-width`),
  недоступное (если появится — отдельный токен, без «просто opacity»).
- Фокус не убирается: `outline: none` без замены запрещён.
- Движение — только `--transition-ui` и `--transition-move`, длительности
  `--dur-*` (при `prefers-reduced-motion` равны 0). Анимируем `transform` и
  `opacity`; `transition: all`, параллакса и скролл-джекинга нет.

## 9. Раскладка и ритм

- Утилиты `styles/layout.css`: `.container`, `.section` (+ `--sunken`,
  `--inverse`, `--flush-top`, `--tight-top`), `.stack` (`--lg`, `--xl`),
  `.split` (`--5-7`, `--7-5`, `--6-6`, `--reverse`, `--start`, `--stretch`),
  `.self-start`. Порядок детей `.split` всегда «текст, медиа».
- **Фоны секций строго чередуются:** Hero → Чему учим (полоса) → Студия →
  Преподаватель (полоса) → Онлайн → Дневник (полоса) → Кабинет → Отзывы
  (полоса) → Цены → Вопросы (полоса) → Адрес → Запись (тёмная). Добавляешь
  секцию — перекрашиваешь соседей; проверяет `audit:ui`.
- **Один паттерн — один вид.** Если элемент повторяется в разных секциях
  (метка секции с тегом, цифры списка, кнопки), он выглядит одинаково при
  любой ширине колонки и длине текста. Расположение не должно зависеть от
  того, «влезло» ли оно. Метка секции с тегом — компонент `Eyebrow`: тег
  всегда на своей строке под меткой. Дубли стилей в секциях запрещены.
- **Композиции секций чередуются.** После Hero идёт ритм «текст слева,
  медиа справа» → «медиа слева, текст справа» → и так далее; две соседние
  секции не могут иметь одну и ту же композицию. Секции во всю ширину
  (отзывы, цены) ритм не продолжают, а прерывают. Текущая последовательность:

  | №   | Секция         | Композиция                   |
  | --- | -------------- | ---------------------------- |
  | 01  | Чему учим      | текст слева, карточки справа |
  | 02  | Студия         | фото слева, текст справа     |
  | 03  | Преподаватель  | текст слева, фото справа     |
  | 04  | Онлайн         | фото слева, текст справа     |
  | 05  | Дневник        | текст слева, макеты справа   |
  | 06  | Личный кабинет | телефоны слева, текст справа |
  | 07  | Отзывы         | во всю ширину (лента)        |
  |     | Цены           | во всю ширину (три карточки) |
  | 08  | Вопросы        | текст слева, список справа   |
  | 09  | Адрес          | карта слева, текст справа    |
  |     | Запись         | тёмный блок, текст слева     |

  Новая секция вставляется так, чтобы ритм сохранился: выбери сторону,
  противоположную предыдущей (`split--reverse` ставит медиа влево), при
  необходимости переверни следующие. Проверяет `audit:ui` (правило
  `composition`).

- Два брейкпоинта: **900px** (колонки встают в одну) и **640px** (телефоны).
  Новых нет. Ширины для проверки: 320, 375, 390, 768, 901, 1280.
- Горизонтального скролла нет; в сетках `minmax(0, 1fr)`; `nowrap` только где
  текст гарантированно короткий.
- Порядок на телефоне: сначала смысл (заголовок, текст), потом медиа; главное
  действие всегда видно без прокрутки на первом экране и повторяется в
  конце страницы.

## 10. UX-правила

- **Одно главное действие на экран.** Сейчас: «Бесплатный урок» (в Hero,
  шапке, секции записи); остальные кнопки вторичные (`outline`).
- Контакты всегда под рукой: телефон и Telegram в верхней строке; ссылки
  Telegram открывают чат с готовым сообщением (`telegramLinks`).
- Навигация: не больше 4 пунктов в шапке; никаких sticky-шапок и плавающих
  чатов; якоря ведут на секции с `id`.
- Каждая ссылка куда-то ведёт; заглушек («скоро», пустой пункт) нет.
- Метки действий конкретные («Написать в Telegram», а не «Подробнее»).
- Сайт не собирает данные: нет форм, счётчиков и сторонних скриптов без
  явного решения владельца; внешние встраивания (карта, видео) — по клику.
- Тексты — на «ты» в лидах как в утверждённом копирайте; новые формулировки
  идут «на согласование» владельцу.

## 11. Доступность и разметка

- `<main id="main">` и ссылка «Перейти к содержимому»; у каждой картинки
  `alt` (декоративная — `alt=""`); декоративные SVG с `aria-hidden`.
- Секции-цели ссылок имеют `id`: `programs`, `studio`, `teacher`, `cabinet`,
  `prices`, `faq`, `booking`. Ссылка без `href` недопустима.
- Внешние ссылки `target="_blank"` — только с `rel="noopener noreferrer"`.
- Все элементы управления достижимы с клавиатуры (Tab, Enter, Space);
  раскрывающийся FAQ — нативный `<details>`.

## 12. Темы

Светлая и тёмная; по умолчанию следует системной (`color-scheme: light dark`),
ручной выбор хранится только в `localStorage` («Авто / Светлая / Тёмная» в
подвале, иконка в шапке). Скрипт в `<head>` ставит `data-theme` до
отрисовки. `theme-color` браузера синхронизируется с темой. Любое изменение
вида проверяется в обеих темах и на **продакшен-сборке**: сборщик
переписывает `light-dark()`.

## 13. Изображения и производительность

- Только WebP, сжатые заранее (`cwebp -q 82`, длинная сторона ×2 от показа);
  у `<Image>` заданы `width`/`height`; пути через `withBasePath()`.
- Шрифты только через `next/font`; без стороннего JS и cookie.
- Первый экран: главное фото с `priority`; остальное — ленивая загрузка.

## 14. Известные пробелы

- Нет `canonical`, `og:` тегов, `sitemap.xml`, `robots.txt`: нужны после
  покупки домена.
- Нет автоматической проверки клавиатурной навигации и скринридера.
- Нет юнит-тестов: проект состоит из статической разметки, качество держится
  на линте, типах, сборке и `audit:ui`.
