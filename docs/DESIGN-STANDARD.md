# Стандарт дизайна и вёрстки — «Ритмология»

Единый документ: что считается правильным на этом сайте и как это проверяется.
Правила для агентов (`AGENTS.md`) и карта проекта (`README.md`) ссылаются сюда.
Если правило здесь расходится с другим файлом, прав этот документ.
Значения токенов живут только в `src/styles/tokens.css`; здесь они названы по
имени, чтобы документ не устаревал при смене цвета или размера.

## 0. Как это проверяется

| Что | Чем | Когда |
|---|---|---|
| «Сырые» цвета, px, шрифты, `style={{}}`, чужие токены, паритет тем | `npm run lint` (ESLint + `scripts/check-design-tokens.mjs`) | на каждый коммит и в CI |
| Типы и сборка | `npx tsc --noEmit`, `npm run build` | в CI |
| Контраст AA, шкала шрифтов, зоны нажатия, горизонтальный скролл, заголовки, `alt`, якоря, чередование фонов, `rel=noopener`; светлая и тёмная тема, 1280 и 390 px | `npm run audit:ui` (нужны запущенный сайт, Node 22, Chrome) | перед каждой выкладкой |
| Самопроверка аудита | `SELFTEST=1 npm run audit:ui` — обязан упасть | после правок самого аудита |
| Навигация клавиатурой, скринридер, «на глаз» (иерархия, ритм) | вручную | при новой секции или компоненте |

Определение «готово»: линт и сборка зелёные, `audit:ui` зелёный, обе темы
просмотрены глазами на 390 и 1280 px, README/AGENTS обновлены, если появилась
секция или компонент.

## 1. Токены: три слоя

1. **Палитра** (`--cream-*`, `--ink-*`, `--red-*` …): только внутри `tokens.css`.
2. **Роли** (`--surface-*`, `--text-*`, `--color-accent*`, `--line-*`): то, чем
   пользуются компоненты. Нужен новый смысл цвета — добавь роль.
3. **Шкалы** (`--fs-*`, `--fw-*`, `--lh-*`, `--space-*`, `--radius-*`,
   `--control-h-*`, `--hit-min`, `--dur-*`).

Компонент может объявлять локальные токены из слоёв 2–3 (`--btn-bg`,
`--card-bg`), но не слоя 1. Хардкод цвета, размера или шрифта в компоненте
считается ошибкой, её ловит линт.

## 2. Цвет

Каждая тематическая роль — одна строка `light-dark(светлая, тёмная)` плюс
светлое значение в блоке `@supports not`.

| Задача | Роль |
|---|---|
| Фон страницы / чередующаяся полоса / карточка | `--surface-page` / `--surface-sunken` / `--surface-raised` |
| Тёмный блок в обеих темах (запись, подвал, выделенная карточка) | `--surface-inverse`, `--surface-featured` |
| Основной / обычный / приглушённый текст | `--text-strong` / `--text-body` / `--text-muted` |
| Текст на тёмном блоке | `--text-inverse`, `--text-inverse-muted` |
| Заливка акцента (кнопка, тег, полоса) | `--color-accent` (+ `-hover`, `-press`, `--color-on-accent`) |
| Акцент как **текст или линия** | `--color-accent-text` |
| Акцент как мелкий текст (14px, цифры) | `--color-accent-text-small` |
| Линии | `--line-hairline`, `--line-strong`, `--line-inverse` |
| Состояния | `--status-ok`, `--status-warn` |

Правила: не полагайся на то, что `--text-strong` тёмный; текст не светлее
4,5:1 к фону (3:1 для крупного ≥24px или ≥18,66px жирного); фоны секций
строго чередуются (раздел 6).

## 3. Типографика

2 семейства (Golos Text — текст; JetBrains Mono — метки, цифры, контакты),
3 начертания (400 / 600 / 800), шкала размеров фиксированная.

| Токен | Размер | Где |
|---|---|---|
| `--fs-xs` | 12 | теги, заголовки колонок подвала |
| `--fs-sm` | 14 | метки секций, моно-подписи, ссылки шапки, цифры пунктов |
| `--fs-md` | 16 | основной текст, кнопки |
| `--fs-lg` | 20 | лид-абзац, значки |
| `--fs-xl` | 44 | цена |
| `--fs-h2` | 22→44 (плавающий) | заголовок секции |
| `--fs-display` | 40→88 (плавающий) | заголовок первого экрана |

Межстрочный: `--lh-none` (1, только значки и кнопки-квадраты), `--lh-tight`
(1,1; заголовки), `--lh-snug` (1,3; метки, UI), `--lh-body` (1,55; текст).
Трекинг: только `--ls-*`. Весь текст идёт через компоненты `ui/Typography.tsx`
(`SectionLabel`, `SectionHeading`, `Lead`, `Body`, `Meta`, `Index`, `Accent`,
`DisplayHeading`); стилизовать заголовки и абзацы в CSS секции нельзя. Один
`h1`, уровни заголовков без пропусков.

## 4. Отступы, форма, элементы управления

- Отступы: `--space-1…8` (4, 8, 12, 16, 24, 32, 48, 64 px); между колонками
  `--col-gap`; между секциями `--section-y`; ширина `--container`, поля `--gutter`.
- Форма: радиусы `--radius-1` (2), `--radius-2` (4), `--radius-pill`; рамка
  телефона `--device-radius`, `--device-border`; линии `--border-hairline`,
  `--border-strong`, `--border-heavy`.
- Кнопки: `sm | md | lg` = `--control-h-sm|md|lg` (40 / 48 / 56 px); варианты
  `primary | outline | dark | inverse | inverseOutline`; `square` для значков.
- **Зоны нажатия:** любая ссылка, кнопка и `summary` не ниже `--space-5`
  (24px) на десктопе и `--hit-min` (44px) на телефоне. Увеличивай `min-height`,
  а не шрифт.
- Движение: только `--transition-ui` и `--transition-move`, длительности
  `--dur-*` (в `prefers-reduced-motion` равны 0). Никаких `transition: all`,
  параллакса, скролл-джекинга.
- Фокус: `:focus-visible` с `--focus-ring`; `outline: none` без замены запрещён.

## 5. Компоненты (`src/components/ui/`)

`Button`, `Card` (тона `paper | plain | featured | inverseOutline`), `Frame` +
`Photo` (кадр с пропорцией; `Photo` сам добавляет basePath), `PhoneFrame`
(`cutout | dark`), `Tag`, `Logo`, `StripeRule`, `PriceCard`, `FaqItem`,
`MapEmbed` (встраивание только по клику), `ThemeToggle`, `ThemeIconButton`,
`Typography`. Новый блок, повторяющийся в двух местах, — компонент; новый вид
кнопки или карточки — несколько локальных токенов в их модуле.

## 6. Раскладка и ритм

- Утилиты `styles/layout.css`: `.container`, `.section` (+ `--sunken`,
  `--inverse`, `--flush-top`, `--tight-top`), `.stack` (`--lg`, `--xl`),
  `.split` (`--5-7`, `--7-5`, `--6-6`, `--reverse`, `--start`, `--stretch`),
  `.self-start`. Порядок детей `.split` всегда «текст, медиа».
- **Фоны секций строго чередуются:** Hero → Чему учим (полоса) → Студия →
  Преподаватель (полоса) → Онлайн → Дневник (полоса) → Кабинет → Отзывы (полоса)
  → Цены → Вопросы (полоса) → Адрес → Запись (тёмная). Добавляешь секцию —
  перекрашиваешь соседей; проверяет `audit:ui`.
- Два брейкпоинта: **900px** (колонки встают в одну) и **640px** (телефоны).
  Новых нет. Проверка ширин: 320, 375, 390, 768, 901, 1280.
- Горизонтального скролла нет; в сетках `minmax(0, 1fr)`; `nowrap` только где
  текст гарантированно короткий.

## 7. Доступность и разметка

- `<main id="main">`, ссылка «Перейти к содержимому», у каждой картинки `alt`
  (декоративная — `alt=""`), декоративные SVG с `aria-hidden`.
- Секции, на которые ведут ссылки, имеют `id`: `programs`, `studio`, `teacher`,
  `cabinet`, `prices`, `faq`, `booking`. Ссылка без `href` недопустима.
- Внешние ссылки `target="_blank"` — только с `rel="noopener noreferrer"`.
- Контраст — раздел 2. Клавиатура: все элементы управления достижимы Tab,
  раскрывающийся FAQ — нативный `<details>`.

## 8. Темы

Светлая и тёмная; по умолчанию следует системной (`color-scheme: light dark`),
ручной выбор хранится только в `localStorage` (`Авто / Светлая / Тёмная` в
подвале, иконка в шапке). Скрипт в `<head>` ставит `data-theme` до отрисовки.
`theme-color` браузера синхронизируется с темой. Любое изменение вида проверяй
в обеих темах и на **продакшен-сборке**: сборщик переписывает `light-dark()`.

## 9. Изображения, производительность, приватность

- Только WebP, сжатые заранее (`cwebp -q 82`, длинная сторона ×2 от показа);
  у `<Image>` заданы `width`/`height`; пути через `withBasePath()`.
- Шрифты только через `next/font`; без стороннего JS и cookie. Карта и любое
  будущее видео грузятся по клику. Сайт не собирает персональные данные: форм,
  счётчиков и скриптов нет без явной просьбы владельца.

## 10. Копирайт и контент

Тексты согласованы с владельцем и не правятся без запроса; весь контент — в
`src/lib/content.ts`. Факты (цены, условия, адрес) придумывать нельзя.
Ссылки на Telegram берутся из `telegramLinks`. Новые тексты секций помечаются
как «на согласование». Заглушек на сайте нет: пункты без реального перехода
не добавляются.

## 11. Известные пробелы (честно)

- Нет `canonical`, `og:` тегов, `sitemap.xml`, `robots.txt`: нужны после покупки
  домена.
- Нет автоматической проверки клавиатурной навигации и скринридера.
- `audit:ui` не запускается в CI (нужен Chrome и Node 22; CI на Node 20).
